Deep Technical Audit: https://github.com/DiabloNova/seorchable

I audited the current public main tree plus the deployed Vercel app, including route structure, configuration, authentication, crawling, database code, migrations, frontend components, logs, and live robots.txt / sitemap.xml behavior.

Verdict: do not treat this as production-ready. The largest blockers are broken authentication, missing runtime dependencies/files, unauthenticated premium crawling, silent database fallbacks, and invalid SEO endpoints.

A) Frontend Issues & UI/UX Bottlenecks
A1. Hydration mismatch is confirmed

Path: src/components/ThemeProvider.tsxEvidence: dev_server.log reports a React hydration mismatch on /fa.

Root cause: The server renders locale and direction from route params, while the client later reads localStorage and matchMedia, then mutates <html lang>, <html dir>, and theme classes. The server and first client render can disagree.

Severity: High

Exact fix:
1. Resolve language and theme from cookies on the server.
2. Pass initialLanguage and initialTheme into ThemeProvider.
3. Do not mutate <html> during the first hydration cycle.
4. Use a tiny blocking theme script only if system theme detection is required.
5. Add a hydration regression test for /fa and /en.
---
A2. The landing page is unnecessarily client-rendered

Paths:
• src/app/[locale]/page.tsx
• src/app/page.tsx

Both are approximately 70 KB and use "use client".

Root cause: The complete marketing homepage, copy, navigation, tabs, graphs, and audit funnel are bundled into a client boundary. The repository also contains two large landing-page implementations, creating duplication and drift.

Severity: High

Exact fix:
• Convert src/app/[locale]/page.tsx into a Server Component.
• Extract only interactive pieces into client islands:
  • FreeAuditPanel
  • dashboard preview tabs
  • LiveKnowledgeGraph
• Remove or redirect the duplicate src/app/page.tsx.
• Dynamically import heavy visualizations:const LiveKnowledgeGraph = dynamic(
  () => import("@/components/features/graph/LiveKnowledgeGraph"),
  { ssr: false }
);

• Keep marketing copy, headings, pricing, and trust content server-rendered.

This should materially improve JavaScript payload, TBT, LCP, and crawl reliability.

A3. The public audit UI is a simulation, not the backend product

Path: src/components/features/audit/FreeAuditPanel.tsx

Root cause: The component calls:
auditService.provisionAuditJob(url)
auditService.simulateCrawlingAndAnalysis(...)


The service is explicitly a mock implementation in src/services/auditService.ts. The UI displays generated scores, generated crawl logs, and randomized results.

Severity: Critical for product correctness

Exact fix:
• Replace the mock service call with /api/v1/audit/free.
• Return a real job ID or real audit result.
• Display server status, provider errors, partial results, and retry state.
• Persist the audit result server-side.
• Clearly label any intentionally simulated demo mode.

The current UI presents fabricated analysis as a completed technical audit.

A4. Password input is misleading and authentication state can become inconsistent

Paths:
• src/components/AuthProvider.tsx
• src/components/features/audit/FreeAuditPanel.tsx
• src/app/actions/auth.ts

Root cause: AuthProvider.login(email, password) calls:
loginAction(email)


The password is discarded. Registration similarly calls:
registerAction(name, email)


The password is never sent.

Severity: Critical

Exact fix:
• Change action signatures to accept password.
• Validate password server-side with Zod.
• Hash passwords using Argon2id or a vetted scrypt implementation.
• Store only the password hash.
• Verify the password during login.
• Never use email-only authentication.
• Add rate limiting and lockout controls.
• Return generic credential errors.

A5. Client-only route protection is not sufficient

Path: src/components/ProtectedRoute.tsx

Root cause: Protection is performed through a client useEffect and router.push(). This allows protected UI to be initially rendered or requested before the client session check completes. It also uses push() instead of replace().

Severity: High

Exact fix:
• Protect the (dashboard) route group through a server layout.
• Call requireSession() in the server layout.
• Perform role checks on the server.
• Keep ProtectedRoute only as a UX fallback, not as the security boundary.
• Use router.replace() for redirects.
• Memoize hasPermission in AuthProvider.
---
A6. Permission callback identity causes unnecessary effects

Path: src/components/AuthProvider.tsx

Root cause: hasPermission is recreated on every render. ProtectedRoute includes it in its effect dependency list, causing the effect to rerun whenever auth state changes.

Severity: Medium

Exact fix:
const hasPermission = useCallback(
  (requiredRole: UserRole) => {
    ...
  },
  [session.user]
);


Also avoid redirecting repeatedly when already on the target route.

The active workspace selector changes local UI state but does not change the authenticated tenant or reload data.

A8. Live canvas renderer restarts too often

Path: src/components/features/graph/LiveKnowledgeGraph.tsx

Root cause: The animation effect depends on liveValues and hoveredCurveIndex. Every 900 ms, the live values update and the entire requestAnimationFrame loop is destroyed and recreated.

Severity: Medium

Exact fix:

• Keep the animation loop stable.
• Update displayed values at a throttled interval.
• Pause animation when document.visibilityState === "hidden".
• Respect reduced motion by disabling both RAF and interval updates.
• Add keyboard-accessible equivalents for hover tooltips.

A9. Accessibility gaps

Paths:
• src/components/features/audit/FreeAuditPanel.tsx
• src/components/features/graph/LiveKnowledgeGraph.tsx

Severity: High

Exact fix:

• Add aria-live="polite" only for meaningful status changes.
• Run axe, Lighthouse accessibility, and keyboard-only tests.

B) Backend, Data Layer & API Architecture
B1. System context never creates a database client

Paths:
• src/core/database/tenant-context/index.ts
• src/app/actions/auth.ts
• src/services/auth/authorization.ts

Root cause: runWithSystemContext() creates a context with no dbClient:
const ctx = Object.freeze({
  tenantId: null,
  userId,
  requestId,
  executionMode: "system"
});


But callers immediately do:
const client = TenantContextManager.getDbClient();
if (!client) {
  throw new Error("Failed to get DB client in system context");
}


Therefore login, registration, password reset, membership checks, and role resolution fail whenever those paths execute.

Severity: Critical

Exact fix:
• Lease a dedicated PostgreSQL client inside system context.
• Store it in TenantContext.
• Release it in finally.
• Use a restricted system DB role.
• Explicitly permit only system tables and membership queries.
• Do not use system mode as an unrestricted bypass.

This is the primary reason the authentication flow is broken.
---
B2. Premium audit authorization bypass

Path: src/app/api/v1/audit/premium/route.ts

Root cause: The route trusts:
const tenantId = req.headers.get("x-tenant-id");
const userId = req.headers.get("x-user-id") || "usr-premium-default";


It does not call getSession(), authorizeApiRequest(), requireWorkspaceMembership(), or a subscription check.

Severity: Critical

Impact:
• An unauthenticated caller can submit expensive crawl requests.
• Tenant IDs are caller-controlled.
• Database writes execute under the requested tenant context.
• There is no demonstrated quota or paid-plan enforcement.
• Firecrawl and LLM costs can be abused.

Exact fix:
const identity = await authorizeApiRequest(req);
await requireWorkspaceMembership(
  identity.userId,
  identity.tenantId
);
await requireRole("workspace_admin", identity.tenantId);
await assertActiveSubscription(identity.tenantId);


For external API integrations, replace arbitrary headers with hashed API keys or signed service tokens. Never accept user identity from a plain header.
---
B3. Audit engine route has the same tenant trust problem

Path: src/app/api/v1/audit/engine/route.ts

Root cause: The route reads x-user-id and x-tenant-id, including a default user ID, and executes database work without a verified session or API credential.

Severity: Critical

Exact fix:
• Remove default identities.
• Require a signed session or API key.
• Resolve tenant identity from the credential, not the request body/header.
• Verify membership before entering tenant context.
• Apply rate limits and quotas.

B4. Public free audit endpoint is abuseable

Path: src/app/api/v1/audit/free/route.ts

Root cause: The free endpoint is publicly callable and directly invokes Firecrawl when configured. There is no evident rate limiting, IP quota, CAPTCHA/abuse control, job queue, or provider budget guard.

Severity: High

Exact fix:
• Add IP and account-based rate limits.
• Add per-domain cooldowns.
• Enforce daily crawl quotas.
• Queue work instead of holding the HTTP request open.
• Validate HTTP/HTTPS only.
• Apply SSRF and DNS rebinding protection.
• Add provider cost ceilings.
• Return 202 Accepted with polling or streaming status.
---
B5. SSRF validation is inconsistent

Paths:
• src/features/acquisition/infrastructure/security/ssrf-guard.ts
• src/app/api/v1/audit/premium/route.ts
• src/app/api/v1/audit/free/route.ts

Root cause: The robust SSRF guard exists for the crawl orchestrator, but the free and premium audit routes call Firecrawl directly and bypass it.

The premium validator only uses z.string().url(), which is not an SSRF policy.

Severity: High

Exact fix:
• Centralize URL normalization and host validation.
• Reject non-HTTP(S) schemes.
• Resolve DNS immediately before every outbound connection.
• Reject private, loopback, link-local, CGNAT, multicast, documentation, and IPv4-mapped IPv6 addresses.
• Revalidate every redirect target.
• Bind outbound requests to the validated IP where supported.
• Disable unrestricted redirects.

B6. Database outages silently become mock success

Paths:
• src/features/admin/infrastructure/persistence/postgres/index.ts
• src/core/database/tenant-context/index.ts
• src/app/api/v1/audit/premium/route.ts

Root cause: PostgresClient.connectClient() catches connection errors and creates MockPoolClient. The premium audit route also catches database write errors and still returns a successful audit response.

Severity: Critical

Impact: Users can receive results that were never persisted. Operators can believe the system is healthy while the database is unavailable.

Exact fix:
• Remove production fallback drivers.
• Allow mock drivers only under an explicit MOCK_SERVICES=true development flag.
• Fail health checks when the database is unavailable.
• Return a provider/database error instead of fake success.
• Never swallow persistence failure for a paid audit.
• Add transaction outcome telemetry and alerts.
---
B7. Global transaction state is not request-safe

Path: src/features/admin/infrastructure/persistence/postgres/index.ts

Root cause: PostgresClient stores transaction state in singleton fields:
private inTransaction = false;
private currentTransactionOperations = [];


Concurrent requests can share this mutable state.

Severity: High

Exact fix:
• Delete singleton transaction state.
• Use the leased PoolClient stored in AsyncLocalStorage.
• Make transaction ownership request-scoped.
• Use BEGIN, COMMIT, and ROLLBACK on the leased client.
• Add concurrency tests with parallel tenant requests.

B8. Migration tooling is misconfigured

Paths:
• src/core/database/migrator.ts
• package.json
• database/migrations
• database/schema

Root cause: The migrator points to:
database/drizzle


The repository contains database/migrations, not database/drizzle.

The package also declares scripts using drizzle-kit, but the manifest does not declare drizzle-kit or drizzle-orm.

Severity: Critical

Exact fix:

Choose one migration system:

  • Add drizzle-orm and drizzle-kit.
  • Add drizzle.config.ts.
  • Generate migrations into one canonical directory.
  • Update the migrator to use that directory.
2. Raw SQL:
  • Remove Drizzle migration scripts.
  • Apply database/migrations through a deterministic migration runner.
  • Record checksums and applied versions.

Do not maintain parallel schema sources.

B11. Session secret is unstable when environment configuration is missing

Path: src/services/auth/session.ts

Root cause:
const SESSION_SECRET =
  process.env.SESSION_SECRET || crypto.randomBytes(32).toString("hex");


Every process restart or serverless cold start can create a different signing key.

Severity: High

Exact fix:

• Validate it at startup.
• Store it in the deployment secret manager.
• Fail fast if it is missing.
• Rotate through a key ring with kid support if rotation is required.

B13. Firecrawl and LLM requests run synchronously without hard deadlines

Path: src/app/api/v1/audit/premium/route.ts

Severity: High

• Add provider timeout and cancellation.

export default function robots(): MetadataRoute.Robots {

          "/settings",
          "/profile",

}


Ensure the deployed domain and canonical domain are the same.

C3. Locale metadata is not actually localized

Path: src/app/[locale]/layout.tsx

Root cause: Metadata is static for both locales. There is no locale-specific canonical URL, hreflang, OpenGraph locale, or alternate language mapping.

Severity: High

Exact fix:

Implement generateMetadata():
export async function generateMetadata({
  params,
}: {
  params: Promise<{ locale: "fa" | "en" }>;
}): Promise<Metadata> {
  const { locale } = await params;
  const url = `https://seorchable.ir/${locale}`;

  return {
    metadataBase: new URL("https://seorchable.ir"),
    alternates: {
      canonical: url,
      languages: {
        fa: "https://seorchable.ir/fa",
        en: "https://seorchable.ir/en",
      },
    },
    openGraph: {
      url,
      locale: locale === "fa" ? "fa_IR" : "en_US",
      alternateLocale: locale === "fa" ? ["en_US"] : ["fa_IR"],
      images: ["/og.png"],
    },
  };
}
