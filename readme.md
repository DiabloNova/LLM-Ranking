# سئورچبل (SEOrchable)

> **زبان‌ها:** فارسی (این فایل) · [English](./readme-eng.md)

پلتفرم هوشمندی و پایش دیده‌شدن برند در موتورهای پاسخ و مدل‌های زبانی بزرگ.

---

## پروژه چیست

موتورهای جست‌وجو دیگر تنها مقصد کاربر نیستند. بخش بزرگ و روبه‌رشدی از پرسش‌ها امروز مستقیماً در ChatGPT، Gemini، Claude و Perplexity پاسخ داده می‌شود؛ جایی که کاربر پاسخ را می‌گیرد و هرگز روی هیچ لینکی کلیک نمی‌کند. در این وضعیت، ابزارهای سنتی سئو دیگر پرسش درست را پاسخ نمی‌دهند. آن‌ها می‌گویند شما در رتبه‌ی چند گوگل هستید، اما نمی‌گویند وقتی کسی از یک مدل زبانی درباره‌ی حوزه‌ی کاری شما می‌پرسد، **آیا نام برند شما گفته می‌شود، چگونه توصیف می‌شود، و در کنار چه رقبایی قرار می‌گیرد.**

سئورچبل برای پاسخ به همین پرسش ساخته شده است.

این پلتفرم سه لایه‌ی به‌هم‌پیوسته را پوشش می‌دهد:

- **AEO (بهینه‌سازی برای موتورهای پاسخ):** سنجش این‌که برند شما در پاسخ‌های تولیدشده توسط مدل‌های زبانی چگونه و با چه دقتی حاضر می‌شود.
- **GEO (بهینه‌سازی برای جست‌وجوی مولد):** تحلیل جایگاه شما در نتایج جست‌وجوی مولد و شناسایی شکاف‌های معنایی نسبت به رقبا.
- **سئوی فنی و گراف دانش:** ممیزی زیرساخت فنی، داده‌ی ساخت‌یافته و روابط موجودیت‌ها؛ همان چیزی که تعیین می‌کند مدل‌های زبانی محتوای شما را چقدر درست بفهمند.

## هدف از توسعه

بازار ابزارهای سئو پر از محصولاتی است که یک شاخص را اندازه می‌گیرند و کار را تمام‌شده می‌دانند. مشکل واقعی تیم‌های بازاریابی و سئو این نیست که داده کم دارند؛ این است که داده‌هایشان در چند ابزار جدا پخش شده و هیچ‌کدام تصویر کاملی از «برند ما در لایه‌ی هوش مصنوعی چگونه دیده می‌شود» نمی‌دهد.

هدف سئورچبل ساختن یک منبع واحد حقیقت برای دیده‌شدن برند است: از خزش سایت و استخراج موجودیت‌ها، تا پایش ارجاعات در مدل‌های زبانی، تحلیل رقابتی، و تولید توصیه‌های محتوایی قابل اجرا؛ همه در یک محصول و روی یک مدل داده‌ی مشترک.

سه اصل طراحی که پروژه بر آن‌ها بنا شده است:

1. **جداسازی کامل داده‌ی مستأجران.** هر سازمان یک مرز داده‌ای مستقل است که با Row Level Security در سطح PostgreSQL اعمال می‌شود، نه با فیلتر در لایه‌ی برنامه.
2. **شکست آشکار، نه شکست خاموش.** هر خطای زیرساختی باید به‌صورت خطا دیده شود. هیچ مسیری در محصول اجازه ندارد نبود داده را به‌جای داده‌ی واقعی نمایش دهد.
3. **پارسی به‌عنوان زبان اصلی.** رابط کاربری و خروجی تحلیل‌ها از ابتدا دوزبانه (فارسی RTL و انگلیسی LTR) طراحی شده‌اند، نه به‌عنوان ترجمه‌ی افزوده.

## معماری فنی

| لایه | فناوری |
|---|---|
| فریم‌ورک | Next.js 16.2.11 (App Router) · React 19.2.4 · TypeScript |
| پایگاه داده | PostgreSQL با Drizzle ORM · جداسازی مستأجر با RLS |
| صف کارها | Inngest برای کارهای طولانی (خزش، فراخوانی مدل زبانی) |
| کش و محدودسازی نرخ | Upstash Redis |
| خزش وب | Firecrawl |
| مدل زبانی | Google Generative AI SDK |
| اعتبارسنجی | Zod |
| رابط کاربری | Tailwind CSS v4 · Framer Motion · Recharts |

### ساختار پوشه‌ها

```
src/app/[locale]/     صفحات بازاریابی و داشبورد (fa و en)
src/app/api/          هندلرهای HTTP
src/app/actions/      Server Actions
src/services/         سرویس‌های میان‌برشی (احراز هویت، خزنده، AI)
src/features/         ماژول‌های عمودی محصول (دامنه / کاربرد / زیرساخت)
src/core/             پایگاه داده، کش، کانتینر، بافت مستأجر
database/schema/      تعریف جداول Drizzle (منبع حقیقت)
database/migrations/  مهاجرت‌های SQL دست‌نویس
docs/                 مستندات محصول و معماری
tests/                آزمون‌ها
```

## راه‌اندازی

**پیش‌نیازها:** Node.js 20 یا بالاتر · pnpm · دسترسی به یک نمونه PostgreSQL

```bash
pnpm install
cp .env.example .env.local
# متغیرهای محیطی را در .env.local مقداردهی کنید
pnpm db:migrate
pnpm dev
```

اپلیکیشن روی `http://localhost:3000` بالا می‌آید.

### متغیرهای محیطی

فهرست کامل و توضیح هر متغیر در `.env.example` آمده است. متغیرهایی که در محیط production **الزامی** هستند:

| متغیر | نقش |
|---|---|
| `DATABASE_URL` | اتصال زمان اجرا به PostgreSQL |
| `SESSION_SECRET` | کلید امضای کوکی نشست؛ حداقل ۳۲ کاراکتر |
| `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` | کش و محدودسازی نرخ |
| `FIRECRAWL_API_KEY` | خزش وب |
| `GOOGLE_GENERATIVE_AI_API_KEY` | تحلیل معنایی |

> **هشدار:** `MIGRATION_DATABASE_URL` تنها برای اجرای مهاجرت‌ها است و هرگز نباید در کد زمان اجرا، مسیرهای API، یا سمت کلاینت استفاده شود. مهاجرت‌ها هیچ‌گاه در جریان `next build` یا در زمان استارت اپلیکیشن اجرا نمی‌شوند.

## دستورهای پروژه

```bash
pnpm dev                # سرور توسعه
pnpm build              # بیلد production
pnpm start              # اجرای بیلد
pnpm lint               # ESLint
pnpm exec tsc --noEmit  # بررسی نوع‌ها
pnpm db:generate        # تولید مهاجرت با drizzle-kit
pnpm db:migrate         # اعمال مهاجرت‌ها
pnpm test:acquisition   # آزمون‌های ماژول acquisition
```
